# План отдельных сборок 6.12 и сохранения каналов

Подготовлено 12 октября 2026 года. Это план последующей реализации. Полная сборка 6.12 не запущена; текущие исходники, `.config`, shell-скрипты, профили и lock Linux 6.6 не менялись. Проверенные небольшие файлы двух ревизий сохранены в `/tmp/ax6000-612-plan`.

## Порядок и изоляция

Сначала завершить текущую сборку Linux 6.6: прошивка stock, соответствующий SDK, все совместимые выбранные kmods и проверенная подписанная публикация. Затем создать отдельный git-репозиторий `/home/valuxin/dev/owrt/ax6000-packages-6.12`, сохранив 6.6 как самостоятельную линию. Скопировать исправленные инструменты из явно зафиксированного commit; не использовать текущий рабочий каталог 6.6 для экспериментальной конфигурации.

Два канала 6.12:

| Канал | Зафиксированный source commit | Ядро | Статус |
|---|---|---|---|
| `recommended` | `ae65e1de69971b5a2e3cf7e39390ee93f274d488` | 6.12.108 | Кандидат до проблемного merge; stock ещё требует проверки на роутере |
| `latest` | `a99b0888b88f134f56bcb2a7d93027b5d20638a9` | 6.12.112 | Зафиксированный исследованный snapshot; известные отчёты о регрессии HNAT |

Оба commit относятся к [chasey-dev/immortalwrt-mt798x-rebase](https://github.com/chasey-dev/immortalwrt-mt798x-rebase). Обоснование и ограничения испытаний приведены в [KERNEL-6.12.md](KERNEL-6.12.md). Название `latest` означает этот явно выбранный snapshot, а не автоматическое переключение ядра на изменяемый HEAD.

Порядок полной компиляции: `recommended/stock`, затем `latest/stock`, затем отдельно `recommended/mtkuboot`, `recommended/ubootmod` и соответствующие альтернативы `latest`. Каждому заданию нужны собственные source/work/output, профиль, lock и resume fingerprint. Общий `dl` допустим; подготовленный kernel tree, staging target и готовые IPK разных поколений смешивать нельзя. Общий build-lock должен охватывать оба репозитория; одновременно работает одна тяжёлая сборка, в прежнем лимите 4 CPU и 10 GiB RAM. На первом этапе строить каждый layout отдельно, выбирая ровно один device.

## Проверенные отличия и необходимые изменения builder

1. **Формат пакетов.** В 25.12 `USE_APK` имеет default `y`. Source configure/select и SDK select должны явно записывать `# CONFIG_USE_APK is not set`, включать `CONFIG_PACKAGE_opkg=y` для образа, сохранять `CONFIG_SIGNED_PACKAGES=y` и `CONFIG_SIGNATURE_CHECK=y` в прошивке. После `defconfig` проверить эти значения и отсутствие выбранного APK package manager. После сборки проверять IPK-выход и manifest образа; выполнить отдельную проверку LuCI package manager с opkg. SDK может отключать собственное индексное подписание: итоговый feed по-прежнему подписывает publisher. Первичные источники: [Kconfig](https://github.com/chasey-dev/immortalwrt-mt798x-rebase/blob/ae65e1de69971b5a2e3cf7e39390ee93f274d488/config/Config-build.in), [opkg](https://github.com/chasey-dev/immortalwrt-mt798x-rebase/blob/ae65e1de69971b5a2e3cf7e39390ee93f274d488/package/system/opkg/Makefile), [выбор IPK/APK](https://github.com/chasey-dev/immortalwrt-mt798x-rebase/blob/ae65e1de69971b5a2e3cf7e39390ee93f274d488/include/package-pack.mk).

2. **Vendor baseline.** Начать с нового `defconfig/mt7986-ax6000.config`, не переносить целиком `.config` 6.6. Он уже использует `mediatek/filogic`, но выбирает множество устройств — оставить только нужный AX6000 device. Сохранить vendor `kmod-mt_wifi`, `kmod-conninfra`, `kmod-warp`, `kmod-mediatek_hnat` в образе, настройки MT7986/MT7976, `AX6000` SKU, driver 7.6.7.3 и firmware `mt7986-fw-20260601`. Два исследованных commit имеют одинаковые проверенные vendor defconfig и Makefile драйвера. [Defconfig](https://github.com/chasey-dev/immortalwrt-mt798x-rebase/blob/ae65e1de69971b5a2e3cf7e39390ee93f274d488/defconfig/mt7986-ax6000.config).

3. **Управление Wi-Fi.** Сохранить `mtwifi-cfg-ucode`, `ucode-mod-datconf`, `ucode-mod-l1parser`, `iwinfo-ucode`, `ucode-mod-iwinfo`, `wifi-dats`, vendor utilities и LuCI `luci-app-mtwifi-cfg`. `mtwifi-cfg-ucode` конфликтует с прежним `mtwifi-cfg`; `iwinfo-ucode` требует отсутствия выбранного `iwinfo`. Для ALL_KMODS отдельно проверить итоговый `WIFI_SCRIPTS_UCODE`: cfg80211 выбирает прежний iwinfo только при `!WIFI_SCRIPTS_UCODE`. Нельзя потерять рабочее управление vendor Wi-Fi ради выбора необязательного kmod. [mtwifi-cfg-ucode](https://github.com/chasey-dev/immortalwrt-mt798x-rebase/blob/ae65e1de69971b5a2e3cf7e39390ee93f274d488/package/mtk/applications/mtwifi-cfg-ucode/Makefile), [iwinfo-ucode](https://github.com/chasey-dev/immortalwrt-mt798x-rebase/blob/ae65e1de69971b5a2e3cf7e39390ee93f274d488/package/network/utils/iwinfo-ucode/Makefile), [cfg80211](https://github.com/chasey-dev/immortalwrt-mt798x-rebase/blob/ae65e1de69971b5a2e3cf7e39390ee93f274d488/package/kernel/mac80211/Makefile).

4. **Feeds.** Packages/LuCI/routing/telephony используют `openwrt-25.12`, а новый vendor feed list содержит также `video`. Зафиксировать полный SHA каждого необходимого feed; video оставить для широкой совместимой выборки, если его пакеты входят в metadata. AWG — отдельный зафиксированный community feed. Старые pins 24.10 не переносить. Source build имеет base-пакеты внутри дерева. SDK base feed теперь формируется как `src-git --root=package base URL^COMMIT`: поддержать этот флаг в профиле/генераторе и проверять HEAD исходного clone, доступного через `feeds/base_root`. Остальные feeds обычные. [feeds.conf.default](https://github.com/chasey-dev/immortalwrt-mt798x-rebase/blob/ae65e1de69971b5a2e3cf7e39390ee93f274d488/feeds.conf.default), [SDK base feed](https://github.com/chasey-dev/immortalwrt-mt798x-rebase/blob/ae65e1de69971b5a2e3cf7e39390ee93f274d488/target/sdk/Makefile), [обработка root](https://github.com/chasey-dev/immortalwrt-mt798x-rebase/blob/ae65e1de69971b5a2e3cf7e39390ee93f274d488/scripts/feeds).

5. **SDK и ABI.** Формат kernel dependency остаётся `kernel (= VERSION~VERMAGIC-rRELEASE)`. Нельзя брать SDK или kmods 6.6. Подготовленный SDK 6.12 сохраняет `.config`, headers/scripts, Module.symvers, modules.builtin и `.ko`, но проверенный список также не содержит `.vermagic`, `.config.set`, modules.builtin.modinfo. Перенести существующее augmentation с проверкой byte-equality `.config`/Module.symvers и дополнением этих файлов. Для каждого full build заново обнаруживать ABI из kernel IPK. [kernel.mk](https://github.com/chasey-dev/immortalwrt-mt798x-rebase/blob/ae65e1de69971b5a2e3cf7e39390ee93f274d488/include/kernel.mk), [SDK](https://github.com/chasey-dev/immortalwrt-mt798x-rebase/blob/ae65e1de69971b5a2e3cf7e39390ee93f274d488/target/sdk/Makefile).

6. **Выбор пакетов.** Сохранить список VPN/Tailscale/AWG/WireGuard/PBR/mwan3/GeoIP и русского LuCI, проверяя реальные symbols 25.12 после `defconfig`; версии пакетов и названия зависят от новых feeds. Tailscale остаётся официальным static ARM64 с проверенной SHA256; Go backport не требуется. ALL_KMODS выбирает только совместимые с новым контекстом модули. Зафиксировать selected/incompatible report и сравнить выбранные имена с реально построенными IPK. AWG на 6.12 требует отдельной полной compile-проверки.

Добавить разрешённый `build_source.device` из таблицы ниже, проверить соответствующий metadata symbol, DTS compatible и ожидаемый image suffix. Все остальные device symbols должны быть выключены. SDK/profile/lock/state нельзя переиспользовать между layout без проверки полного build context.

## Сохранение пакетов полного build

Проверка реального `.packageinfo` и `.config` текущей 6.6 показала 1035 выбранных kmods. Замораживания одних модулей недостаточно: например, r8169 требует r8169-firmware, crypto-hw-safexcel — eip197-mini-firmware, cfg80211 — iw/iwinfo/wifi-scripts/wireless-regdb, batman-adv — виртуальный batctl (выбран batctl-default). Provider-aware metadata closure обнаружила 63 выбранных non-kmod имени вне dependency closure ежедневного списка. Некоторые уже входят в firmware; остальные должны оставаться в feed для установки необязательных модулей.

Для post-build export 6.6 уже добавлена реализация по **окончательным IPK control Depends/Provides**: сохранить frozen kmods и транзитивные userspace/firmware зависимости, включая built virtual providers и альтернативы. Manifest содержит allowlist `frozen_packages`; `frozen_kmods` остаётся отдельным списком. Явно обновляемые requested external/userland пакеты не замораживаются; вновь построенные зависимости заменяют сохранённые копии по Package. Непредоставленная runtime dependency приводит к отказу export с указанием ребра. Publisher по-прежнему исключает kernel/libc/base-files/busybox/opkg из supplemental feed. Регрессия проверяет цепочку module → firmware → library → libc, виртуальный provider, versioned alternative и ежедневную замену свежей библиотеки/AWG. То же поведение перенести в 6.12 после проверки реального SDK.

## Публикация всех каналов

Идентификатор профиля содержит kernel-line, канал и layout, например `redmi-ax6000-612-recommended-stock`. В sibling repository публикация имеет независимые префиксы `channels/recommended/stock/`, `channels/latest/stock/` и аналогичные для альтернатив. В каждом префиксе размещать `profile.json`, `repository.pub`, `state/lock.json`, подписанный feed и ссылки на соответствующие immutable firmware/SDK. Текущий installer поддерживает `PACKAGE_REPOSITORY_URL` — направлять его на точный префикс; проверка совпадения ABI сохраняется. Один настроенный custom feed не переключать на другой канал молча.

`build_id` теперь должен включать digest готового augmented SDK: `id-sourcecommit12-sdksha12`. Это различает полные поколения с одинаковым source commit, но иными feeds/kernel configuration/layout. URL уже опубликованного SDK не менять и не заменять другими байтами. Daily source locks обновляются отдельно от полного firmware generation: изменение source/kernel должно создавать новое поколение firmware+SDK, а не запускать package-only build с новым ядром.

Каждый daily workflow строит только изменившиеся tracks, но deployment содержит **все** опубликованные tracks. Рекомендуемый алгоритм: один сериализованный publish job восстанавливает проверенные durable snapshots всех каналов, заменяет только успешно построенные channel subtrees, проверяет подписи/SDK URLs/manifest/lock каждого канала и атомарно деплоит собранный общий сайт. Непубликовавшиеся channels не создавать как пустые feeds; ошибки/неизменившиеся locks сохраняют последний успешный subtree. Не полагаться на истекающие Actions artifacts как единственное постоянное хранилище; сохранять release snapshot/manifest с digest для восстановления. Неизменённые subtree должны оставаться byte-identical. Между channel publish jobs общий concurrency group, отдельные namespaced artifact names.

SDK и образы целесообразно хранить в immutable GitHub Releases каждого `build_id`, а Pages использовать для каталога и подписанных feeds; фактический SDK URL профиля может вести прямо к release asset. Опубликованный Pages сайт ограничен 1 GB, каждый release asset — менее 2 GiB. До загрузки проверять суммарный объём и отдельные размеры; для большого SDK потребуется уменьшение/раздельный kernel baseline с отдельной проверяемой SHA256, а не необъявленная смена URL. Источники: [Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits), [release limits](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases).

## Проверки при реализации

- После source/SDK defconfig: только разрешённый device, opkg/IPK, подписи в прошивке, vendor driver/ucode chain и обязательные image packages сохранены.
- После world: правильные image metadata/layout, vendor manifest, один kernel identity, точные kernel Depends всех kmods, каждое выбранное имя построено, SDK context совпадает.
- На augmented SDK: compile AWG и запрошенного userspace, daily merge сохраняет frozen module dependency closure и assets, затем проверка усign над распакованным Packages.gz.
- В тесте публикации двух каналов: обновить один; второй profile/lock/feed/signature/SDK link должен сохраниться. Одинаковый source commit с иным SDK даёт другой build_id и URL. Старый URL остаётся доступным.
- Испытания на AX6000 stock — отдельный этап после компиляции: Ethernet, оба диапазона Wi-Fi, WPA2/WPA3, HNAT, VPN/PBR/multi-WAN, производительность и стабильность. Успешная компиляция или чужой mtkuboot release не доказывает успешную загрузку stock.
