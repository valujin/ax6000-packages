# Redmi AX6000: прошивка и подписанные пакеты

Личный репозиторий для **Xiaomi Redmi Router AX6000, stock layout**, на базе
[PadavanOnly ImmortalWrt 24.10 / Linux6.6](https://github.com/padavanonly/immortalwrt-mt798x-6.6).
Сохраняет настройки драйверов MediaTek из форка. Новая прошивка, SDK и пакеты
строятся вместе; ежедневные обновления пакетов используют SDK той же прошивки.
Прошивка роутера выполняется владельцем вручную.

## Состав

- Tailscale: последняя стабильная официальная ARM64-сборка, проверенная SHA256.
- AmneziaWG3.1: модуль, инструменты, netifd и LuCI-протокол.
- WireGuard, OpenVPN, IPsec/strongSwan, дополнительные PPP/L2TP-инструменты.
- PBR и LuCI, mwan3/MultiWAN, banIP и LuCI для GeoIP-блокировок.
- Все доступные для target модули ядра; неприменимые или исключённые Kconfig
  фиксируются в `build-selection.json`.

Не все пакеты включены в образ: часть доступна для последующей установки.
GeoIP-блокировка и маршрутизация по GeoIP — разные задачи; см. [VPN и маршрутизация](docs/ROUTING.md).

## Две версии ядра

`profiles/redmi-ax6000.json` описывает старую установленную прошивку
`r33471-924aaf9416`, Linux6.6.95, ABI`b5eab2158127d54f4b11361a8599235a`.
Публикация для неё выключена: исходный SDK на зеркале уже заменён.
Модули от новой прошивки нельзя ставить на старое ядро.

`profiles/redmi-ax6000-new.json` задаёт сборку новой прошивки с фиксированным
commit`ec9ef10efc65da1e6d1de4e2c043c0e13d08eed8`. После сборки создаётся
профиль с фактическим ABI и SHA256 нового SDK. Проверка ABI обязательна;
репозиторий не подменяет зависимости kernel и не предлагает замену libc/kernel.

## Сборка и автоматизация

[CI, ключи подписи и Pages](docs/CI.md). [Ограниченная локальная сборка](docs/BUILD.md).
[Публикация готовой локальной сборки](docs/PUBLISH.md) через неизменяемый
GitHub Release позволяет загрузить результат на Pages без повторной компиляции.

Ежедневный мониторинг проверяет ветки feeds`openwrt-24.10`, AmneziaWG и стабильный
релиз Tailscale. Неизменившиеся исходники не вызывают повторную сборку. Ошибка
сборки/проверки/подписи сохраняет последнюю успешную публикацию. Обновление базы
прошивки и ядра выполняется отдельно, вручную.

## Подключение после успешной публикации

Сначала установить **соответствующую новую прошивку**, проверить работу Ethernet
и Wi-Fi и точный `opkg status kernel`. Затем подключить её feed. Инструкция и
скрипт подключения проверяют архитектуру и ABI до изменения настроек.
Не использовать feed нового ядра со старой прошивкой.

```sh
# На сервере: быстрые проверки инструментария
python3 -m unittest discover -s tests -v
for script in scripts/*.sh; do bash -n "$script"; done
```

Зелёные тесты инструментария не означают, что образ уже собран или проверен на
реальном роутере. Статус фактической сборки и SHA256 доступны в Actions/артефактах.
